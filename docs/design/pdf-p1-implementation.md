# PDF P1 implementation evidence

Task: PDF P1, linked to the local PDF viewer Solution and daily behavior parity KR. Accepted design: ADR0034; native ownership: ADR0032. This is an implementation checkpoint, not a parity claim.

The private browser display and worker chunks pin `pdfjs-dist` 6.4.299 and matching package assets. Only the display chunk replaces `process`; the worker examines actual globals through `Reflect.get`. An explicit verified `PDFWorker({ port })` avoids the library's default fake-worker fallback. Owner shutdown must destroy the loading task and terminate the actual Worker separately. The worker never imports the PDF scripting sandbox, and document loading must set `enableXfa: false` and `stopAtErrors: true`. Version 6.4 has no `isEvalSupported` option; passing the removed option would provide no protection.

Built-in CMap, standard-font, ICC and codec WASM bytes are embedded in the worker, with exact internal asset addresses and no real URL fallback. The tiny synchronous adapter serves only the ICC and QCMS requests used by the pinned implementation. Queries, fragments, encoded paths, alternate schemes and unknown filenames are rejected. Required JBIG2/OpenJPEG/QCMS modules must compile before readiness; P1 ships no dynamic JavaScript decoder fallback. Binary/font licenses ship in `dist/pdf-licenses.txt`. These operational allowlists do not constitute a browser sandbox or replace a restrictive worker response CSP.

The initial real Electron 42.10 worker proof used a privileged file renderer with Node integration enabled and worker Node integration disabled. All eight inspected worker globals were undefined; the exact real port parsed a fictional PDF and extracted its text. Operational HTTP/file/query asset fetches failed. This proves that bounded realm, port and asset behavior only. The file parent's existing CSP permits more connections than the PDF policy allows.

An exact custom worker protocol bootstrap from the file renderer failed before its handler received any request, with web security enabled and the parent allowing only that worker URL. No origin/CSP bypass was introduced. The stricter PDF boundary is pending the architecture's fixed Node-free document recommendation and a new actual browser proof; no application viewer UI has been implemented at this checkpoint.

Resource policy: current local vault only, captured session identity, canonical containment, file identity and change checks, maximum 64 MiB PDF, 1,000 pages, eight million rendered pixels, supported fragment height 80–2,000 pixels. External roots are explicitly unsupported. Pre/post canonical checks do not claim an atomic filesystem namespace guarantee against a privileged local process concurrently replacing directories.

Synthetic committed fixtures cover a three-page text document, standard fonts, DeviceCMYK, JPX, JBIG2 and a predefined CMap. Poppler rendering is a fixture sanity check, not proof of pinned PDF.js decoding. Actual decoder success and corrupted/blocked WASM failure are required before completion. Search, thumbnails, outline/navigation layouts, selection links and note export remain outside P1.

Primary references checked on 2026-10-15: [distribution](https://mozilla.github.io/pdf.js/getting_started/), [API](https://mozilla.github.io/pdf.js/api/draft/api.js.html), [compatibility and matching versions](https://github.com/mozilla/pdf.js/wiki/Frequently-Asked-Questions), and the installed pinned package source/types. Context7 results were cross-checked against installed 6.4 source because some examples describe older APIs.

The subsequent accepted architecture direction moves display, text and toolbar into a fixed cross-origin Node-free viewer document with its own same-origin worker (four fixed application resources). The initial protocol bootstrap failure remains recorded above; it is not bypassed. The host initiates one exact-origin private-port handshake and never accepts a viewer request for filesystem or network operations. Actual frame/worker isolation and independent CSP proof precede application UI integration.
