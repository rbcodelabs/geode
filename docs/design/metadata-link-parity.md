# Metadata link completeness recommendation

Date: 2026-10-14. Status: recommendation for the separately owned metadata package. Companion ADR: ADR-0031.

The shared wiki parser should own complete source extraction; the renderer cache, headless SDK and outgoing pane consume its same output. Prefer additive optional fields over replacing legacy arrays or changing LinkCache meanings. Preserve existing `links`/`embeds` consumers and plugin-visible object shapes. Any new `frontmatterLinks` representation should be separately typed and optional, because the baseline CachedMetadata has no such field. Distinguish frontmatter links from body links; never attach invented source positions where the public contract only has a key/path.

Compare three approaches: (1) additive shared parser fields plus renderer graph update and cache invalidation, recommended for consistent semantics; (2) renderer-only regex fill-in, fast but duplicates parsing and risks CLI divergence; (3) a new resolved-reference-only API, cleaner as a future boundary but insufficient for existing plugin metadata consumers. Option 1 gives up a smaller diff in exchange for one maintained syntax implementation.

Include authored Markdown internal links, images and property wikilinks using the existing extractor while excluding fenced/inline code and external URLs. Normalize and resolve through existing engine functions. Preserve source offsets exactly. Existing inline wikilink behavior, aliases, heading/block targets, unsupported/oversize scan behavior and unresolved-link counts must not regress. Enforce consistent frontmatter inclusion rules across resolvedLinks/unresolvedLinks, backlinks and headless outgoing projections; avoid counting the same reference twice in a merged legacy/new-field traversal.

Persisted metadata cache invalidation is required: old cache records will otherwise look current by content hash/mtime yet lack new fields. Bump the relevant parser/cache schema version or fingerprint and test migration/rebuild in both desktop/mobile cache readers. Do not infer old-versus-new validity from absent optional fields alone because valid notes can have no matching references. Validate every persisted-cache store/reader and indexer transfer shape; invalidation should cause reparse, never deletion of note content.

Verification: shared parser fixtures for Markdown/wiki/embed/property links including quoting, aliases, encoded paths, heading/block suffixes, CRLF and code exclusions; unit tests comparing live and persisted hydration; resolution/backlinks rebuild tests after target create/rename/delete; SDK outgoing/reference query tests; renderer integration coverage; test that an old-version cache is discarded/rebuilt even with matching timestamps. Report any public source-shape deviation explicitly. The outgoing pane can temporarily project via the shared source extractor rather than waiting for this package, provided both paths use identical parsing and the cache caveat remains visible.
