# Spec: Geode Mobile MVP — Slice 5 Vault Continuity

**Status:** Approved implementation spec under the user-approved mobile program and
[ADR-0007](../adr/0007-mobile-runtime-and-platform-boundary.md).

**Outcome:** A user can select an existing Files-provider folder, reopen the exact same vault
after restart, edit while temporarily offline, and reconcile external changes without silent
overwrite or substitution of an empty vault.

## Problem

The managed Documents vault is a safe local baseline, but it does not provide the desktop/mobile
continuity expected of the full mobile MVP. A Files-provider URL is not a permanent filesystem
path: access is granted through a security-scoped resource, bookmarks can become stale, provider
items can be evicted or temporarily unavailable, and changes can arrive while Geode is suspended.
Treating it like a desktop folder would create false save acknowledgements and last-writer-wins
data loss.

## Constraints and non-goals

- Ordinary vault files remain the source of truth; provider data is never mirrored into a second
  authoritative Geode store.
- Managed vault behavior remains available and unchanged.
- Access is scoped to the selected folder. A bookmark for one vault never authorizes a sibling.
- Device-shaped workspace state, recent bookmarks, reconciliation snapshots, and caches remain in
  the app container keyed by stable vault identity. Portable vault settings may remain in `.geode`.
- No proprietary sync backend, CRDT merge, arbitrary background daemon, or Android picker is part
  of this slice.
- Simulator tests are necessary but not sufficient. iCloud Drive and one third-party File Provider
  require physical-device evidence before release-candidate exit.

## Options considered

| Approach | Advantages | Costs and failure modes |
|---|---|---|
| Copy a selected folder into the managed vault | Simple I/O and predictable performance | Creates two sources of truth and does not provide continuity |
| Operate directly on the provider folder through a persisted security-scoped bookmark | Preserves ordinary files and provider ownership; works with iCloud and compatible providers | Requires balanced access, coordinated I/O, stale-bookmark repair, offline states, and reconciliation |
| Require users to configure a Geode-hosted sync service | Could normalize provider differences | Adds infrastructure, trust, cost, and migration decisions outside the approved architecture |

Use direct provider access with explicit availability and reconciliation states. Do not fall back to
copying or silently create a managed vault when provider access fails.

## Native boundary

Extend the existing first-party Capacitor vault plugin and `VaultRegistryService`; do not expose raw
bookmark bytes or absolute provider URLs to JavaScript.

### Registry operations

- `chooseExternalVault()` presents `UIDocumentPickerViewController` in folder-selection mode.
- A successful selection creates a registry record containing an opaque stable vault ID, display
  name, provider domain plus stable root resource identity when available, encrypted/protected
  bookmark data, and last-known reconciliation fingerprint. The registry ID is generated by Geode;
  it is not derived solely from a marker stored inside the selected folder.
- Cancel leaves the current vault and registry unchanged.
- `openVault(id)` resolves the bookmark and reports one of: ready, stale-refreshed, unavailable,
  permission-revoked, or missing. It never returns a different root under the same ID.
- Reauthorization must prove the newly selected URL represents the intended vault before replacing
  the bookmark. Preserve the stable identity and device-scoped state only after that proof.
- A copied folder may contain the same portable `.geode` marker as its source, but it is a distinct
  provider root and receives a new registry ID. If a provider cannot prove that a selected root is
  the moved original rather than a clone, Geode refuses automatic rebind and asks the user to open
  it as a new vault.
- Security-scope start/stop calls are reference-counted or otherwise balanced across success,
  throw, cancellation, vault switch, scene disconnect, and app disposal.

### File operations

- Every operation resolves a normalized relative path under the active scoped root and repeats the
  existing symlink/prefix containment checks.
- Reads, writes, rename/move, trash, and metadata enumeration use `NSFileCoordinator` with the
  appropriate reading/writing options. A successful write retains the managed-vault failure-atomic
  guarantee.
- Cloud placeholders report a coded `CONTENT_UNAVAILABLE`/offline state. Geode must never interpret
  missing downloaded bytes as an empty file or write zero bytes over a placeholder.
- Permission loss or provider unavailability makes the vault visibly read-only. Dirty editor text
  stays in memory/device recovery state and is not reported saved.
- The native service emits app-originated events with mutation correlation and provider/external
  events without it. Subscriptions and security scopes are disposed together on vault close.

## Reconciliation model

An always-on desktop watcher is not assumed. Reconcile on:

1. successful vault open;
2. app foreground before autosave resumes;
3. provider/item-change notification when available;
4. explicit refresh or reconnect;
5. completion of a previously unavailable placeholder download.

Store a device-local manifest of normalized path, kind, size, and authoritative modification time.
The manifest is derived and disposable. Reconciliation lists the provider in bounded batches,
diffs it against the last durable manifest, and emits one normalized event per semantic change.
Own-write echoes are correlated and suppressed by the shared Vault; uncorrelated external events
remain live. A failed or cancelled scan leaves the previous durable manifest intact and reports
partial/unavailable status rather than emitting deletes for unseen entries.

Folder rename inference may use stable resource identifiers when the provider supplies them.
Without a trustworthy identifier, delete/create is acceptable only when it cannot overwrite a dirty
open document and the UI makes the transition recoverable.

## Dirty-file conflict policy

Before foreground reconciliation, pause autosave dispatch. For each changed path:

- If the editor is clean, load the external version, refresh metadata, and preserve the leaf where
  possible.
- If the editor has unsaved or unacknowledged text and disk differs from its last confirmed base,
  preserve both versions. Do not choose a winner automatically.
- Write the local editor version to a unique sibling conflict file using the same atomic coordinator,
  e.g. `Note (Geode conflict 2026-08-29 143012).md`, with collision-safe numbering. Keep the external
  provider version at the original path.
- Present a conflict state with actions to open both, copy either version, or dismiss after review.
  Dismissal never deletes either file.
- If the conflict copy cannot be written, retain the local text in device recovery storage and keep
  the original path read-only until the user exports, retries, or explicitly discards it.

The exact conflict filename is an interoperability detail and must be generated in one tested helper.
Conflict files participate in normal vault indexing after creation.

## Renderer behavior

- Vault selection distinguishes “On this device” from “Choose folder in Files.”
- Unavailable/revoked/missing states show the vault identity and an explicit Reconnect action; they
  do not route to an empty onboarding state.
- A provider-backed vault advertises `externalVaultFolder: true` only while the native implementation
  and registry are available; read-only/offline state is separate from immutable startup capability.
- Save status distinguishes saving, saved, offline/pending, conflict, and failed. Only native
  acknowledgement advances the confirmed base.
- Foreground reconciliation completes or reaches an explicit recoverable state before queued
  autosaves are allowed to target provider files.

## Test-first delivery

### Contract and renderer tests

- Picker cancel, open/reopen exact identity, inaccessible-vault UI, reconnect, and no empty-vault
  substitution.
- Dirty/clean external edit decisions, deterministic conflict naming, collision numbering, recovery
  fallback, and autosave pause/resume ordering.
- Duplicate/coalesced provider events, interrupted partial manifest, delayed own-write echo, external
  folder rename/delete, and listener/access cleanup.
- Offline placeholder errors never become empty bytes; failed saves remain visibly unconfirmed.

### Native tests and probes

- Bookmark resolve, stale refresh, moved/deleted folder, revoked access, and balanced access counts.
- Coordinated read/write/rename/trash under injected provider delay, error, and cancellation.
- Concurrent app/external writes at coordination boundaries preserve complete bytes and produce a
  documented conflict outcome.
- Case-only and Unicode-normalization collisions, symlink escape, path traversal, folder subtree
  changes, and cloud-placeholder unavailability.
- Foreground reconciliation after edits made while Geode is suspended.

### Device matrix

- Simulator: local provider fixture on current iPhone and iPad, including background/kill/relaunch.
- Physical release evidence: local Files, iCloud Drive with a second-device edit, and one third-party
  File Provider including eviction/re-download and temporary offline behavior.

## Failure invariants

1. A failed operation does not mutate confirmed source bytes.
2. A save is never labelled successful before coordinated durable acknowledgement.
3. Missing access never creates or selects a replacement empty vault.
4. Reconciliation never deletes state based on an incomplete scan.
5. Dirty local text and changed provider bytes are both recoverable.
6. Security-scoped access does not outlive the active vault operation/session and cannot authorize a
   sibling or stale alternate path.
7. A copied vault marker never causes one opaque registry ID to rebind to a different provider root.

## Done when

- A provider-backed vault is selected, reopened by stable identity after cold launch, and remains
  ordinary files visible to the provider.
- iPhone and iPad journeys prove offline edit/reconnect, external clean edit, dirty conflict, provider
  revocation/reconnect, background/foreground, and force-kill/relaunch with exact byte assertions.
- No interruption or injected native failure loses an acknowledged version or reports an unconfirmed
  version as saved.
- Contract, unit, mobile Chromium, native tests/probes, typecheck, full build, parity, and Electron E2E
  gates pass; physical-provider gaps remain explicit until the release-candidate gate.
